# Batch 10 integration architecture
Baseline verified 20713fa (3574 test executions across variants), final audit c6c782d. This is a staged integration, not release approval.
Use existing MultiTimeframeRepository as sole owner of public candle retrieval within the new pipeline; do not create parallel polling clients per symbol. Repository uses public mainnet data only, bounded responses, rate guard and exchange-clock bounds. Existing legacy scanner remains separate until explicitly migrated. Shared global rate budget across legacy and new paths is not yet established.
TimeframeHistory is a data class with caller-supplied list and timestamps; freshness alone does not validate every candle. New provider must validate symbol/frame binding, contiguous closed OHLCV and immutable copies. Repository snapshot is fresh at capture, not indefinitely; consumers must revalidate using trusted exchange time bounds before publishing. No local wall clock substitution.
MasterDecisionEngine requires five independent directional groups plus cross-timeframe alignment. Missing/stale/conflicting evidence means WAIT. No confidence percentage without calibration.
Provider and candle adapter are read-only; no API credentials, order calls, service start or REAL authorization. Next steps: integrate scheduler, indicator/trend/evidence adapters, publication lifecycle and tests. Inspect actual service and legacy scanner before wiring; no duplicate workers. Off-main processing mandatory.
